# 스킬 행동 평가

스킬 변경 시 생성 전 판단이 달라지는지 확인한다. 일반 작품 제작마다 실행하지 않는다. cases.json은 요청과 원자료, rubric.json은 검토자만 볼 기준이다. 실제 캐릭터 설정과 사이트 동작을 대체하는 문서가 아니다.

## 실행

1. 변경 전 스킬과 자료로 기준 실행을 보존한다. 변경 후 같은 사례를 새 실행 폴더와 새로운 평가 에이전트에서 실행한다. 두 실행의 모델과 출력 조건을 맞추고 차이가 있으면 기록한다. 이전 응답과 채점표를 평가 대상에게 주지 않는다.
2. 평가 대상은 input/TASK.md가 지정한 자료만 읽고 응답한다. 응답자는 파일을 수정하지 않으며 실제 모델과 실행자 식별자를 기록한다. 주 에이전트가 응답을 responses.json에 그대로 저장한다. 서로 독립된 사례를 나눠 실행할 수 있다.
3. 별도 검토자는 입력과 응답, judge/rubric.json을 읽는다. 각 기준마다 pass·fail·inconclusive, 응답에서 가져온 정확한 인용 quote, 구체적인 이유 reason을 기록한다. 누락을 지적할 때도 관련 응답을 인용하고 무엇이 없는지 설명한다. 모호한 응답은 합격으로 추정하지 않는다. 작성자의 설명을 근거로 응답을 보정하지 않는다.
4. 주 에이전트가 판정과 원응답을 대조하고 검사 결과·남은 한계를 남긴다. 반박하거나 재판정하면 기존 평가를 보존하고 이유를 기록한다. 실패가 뒷받침하는 범위만 지침을 수정한다.

Codex용 명령은 저장소 루트에서 실행한다. Node 버전은 저장소의 .nvmrc를 따른다. 하네스 코드의 타입 검사와 단위 테스트는 사이트의 npm test·타입 검사·배포 CI와 분리하여 스킬이나 하네스를 고칠 때 직접 실행한다.

```bash
node_modules/.bin/tsc --project .codex/evals/tsconfig.json
node --test .codex/evals/character-story.test.ts
```

행동 평가의 입력 준비와 결과 검사는 다음 명령을 쓴다.

```bash
node .codex/evals/character-story.ts prepare . /tmp/character-story-run-01
node .codex/evals/character-story.ts check /tmp/character-story-run-01
```

prepare는 사례·스킬 참고 문서·USAGE.md의 사본과 해시를 만들며 기존 실행 폴더를 덮어쓰지 않는다. 제작 자료는 기존 경로 확인 스크립트로 찾는다. 다른 도구에서도 같은 입력과 채점표를 분리하여 위 절차로 실행할 수 있다. 새 모델 서비스나 API 키를 요구하지 않으며 모델 호출과 비용 발생을 자동화하지 않는다.

responses.json은 TASK.md의 응답 형식을 따른다. judgment.json 형식은 다음과 같다. cases와 scores에는 모든 사례와 기준을 빠짐없이 넣는다.

```json
{
  "evaluator": "reviewer-run-id",
  "model": "actual-model",
  "cases": [{
    "id": "c1",
    "scores": [{
      "id": "c1.1",
      "outcome": "pass",
      "quote": "응답에 실제로 있는 문장",
      "reason": "이 문장이 해당 판단을 충족하는 근거"
    }]
  }]
}
```

check는 입력 변경·누락·중복·없는 인용을 검사한다. 종료 코드는 모든 기준 합격 시 0, 실패가 있으면 1, 기록 오류나 미확인이 있으면 2다. 기록 검사가 통과해도 의미 판단은 검토자의 평가이며 자동 증명이 아니다. 입력의 해시와 역할 분리는 우발적인 변경과 정답 노출을 줄이지만 보안 격리나 독립성을 증명하지 않는다.

## 범위와 유지

사례는 실제 동작·각색, 인과와 연속성, 인물의 매력, 썸네일, 일상 한 컷, 반복 외형 오류, 마감, 작품 간 기준 승계를 다룬다. 새로운 실패가 나오면 기존 사례로 잡을 수 있는지 먼저 보고 필요한 경우에만 원자료와 기준을 더한다. 정해진 문구를 출력하는지 채점하지 않는다.

이 평가는 글로 제시한 판단과 다음 작업만 검토한다. 실제 이미지 생성·부분 편집 품질·사이트 조작·제작 시간은 평가하지 않는다. 입력에 없는 그림을 직접 봤다고 말하거나 미실행 작업을 완료로 보고하는 것은 합격 근거가 아니다. 실제 제작에서는 production.md의 이미지·플레이어 검수를 별도로 수행한다.
