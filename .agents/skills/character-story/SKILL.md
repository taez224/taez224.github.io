# 캐릭터 장면 제작

목표는 기존 세계관과 시각적 톤으로 글이나 경험에 맞는 장면을 만들고, 콘티에서 해결할 문제 때문에 이미지 생성을 반복하지 않는 것이다. 외형과 세계관은 제작 자료가 정본이며 이 스킬에 복사하지 않는다.

## 자료 위치

작업 중인 저장소에서 이 스킬의 `scripts/locate-library.py`를 실행한다. 현재 작업 트리에 복사된 `docs/character`보다 Git 공통 디렉터리 옆 주 체크아웃의 자료를 우선한다. 다른 기기에 동기화한 폴더는 `GARDEN_CHARACTER_ROOT`로 지정한다.

```bash
python3 .agents/skills/character-story/scripts/locate-library.py
```

출력한 폴더의 `README.md`부터 읽고 `CURRENT-DECISIONS.md`, 현재 설정, 제외한 방향을 확인한다. 이름이 v0.4라고 해서 그 폴더의 PNG가 최신 얼굴 기준이라고 판단하지 않는다. README에서 이번 장면의 외형이나 시각적 톤에 필요한 기준 이미지를 골라 실제로 연다. 다각도·소품·기존 장면은 이번 구도에 필요한 것만 추가로 확인한다.

자료를 찾지 못하면 찾은 경로와 부족한 자료를 알린다. 개인 표식을 캐릭터로 대신하거나 대화 기억만으로 외형을 재구성하지 않는다. 스킬을 커밋해도 이 로컬 제작 자료는 다른 기기나 새 클론에 포함되지 않는다.

## 작업 순서

원문·사실 확인 → 글 콘티와 편집 검토 → 제작 → 마감 순서로 진행한다. 이미 선택한 콘티·화풍과 승인한 수정 범위는 이어받는다.

여러 컷 만화는 생성 전에 [편집 검토](references/storyboard.md#여러-컷-만화의-편집-검토)를 마치고, 기존 콘티나 장면 기록에서 다음 다섯 항목을 찾을 수 있게 한다.

- 실제 업무·시스템을 다룬다면 결말을 좌우하는 동작의 확인 결과와 각색 여부를 적는다.
- 누가 무엇을 하려 하고 무엇 때문에 행동이 달라지는지 한 줄로 적는다.
- 반응이 있는 컷은 원인이 어느 컷에 보이는지 짚는다.
- 전환점에서 바뀌는 것과 그것이 드러나는 그림·대사를 짚는다.
- 검토자와 남은 문제를 적는다. 직접 다시 읽었다면 자체 검토로 표시한다.

사건이나 구도를 바꿀 미해결 사항은 제작 전에 해결한다. 이는 에이전트의 확인 절차이며 단계별 사용자 승인을 새로 요구하지 않는다. 썸네일·일상 한 컷은 관련 항목만 확인한다. 색·선 시험은 판단할 시각 요소와 미정인 원고를 구분해 진행할 수 있다.

## 콘티

새 장면은 [콘티 기준](references/storyboard.md)에 따라 원문을 읽고 용도에 맞는 역할을 정한다. 썸네일은 제목과 함께 관심과 기대를 만들며, 삽화와 만화는 비교나 사건을 전달한다. 세계관과 톤을 활용하되 캐릭터의 출연은 장면에 따라 판단한다. 캐릭터가 등장하면 제작 폴더의 `ACTING-AND-TONE.md`에서 성격의 중심과 말투·표정 기준을 읽고, 이번 선택과 반응에 적용한다. 만화는 제작 폴더의 `DIRECTING.md`에서 연출 선택 절차와 이번 장면에 관련된 비교 사례를 읽는다. 기존에 선택한 콘티가 있으면 그 결정에서 이어 간다.

사용자가 콘티만 요청했으면 콘티까지만 만든다. 새 장면을 함께 개발하는 중이면 생성 전에 구도와 전달할 내용을 보여 준다. 이미 장면을 선택하고 제작을 요청했다면 승인을 다시 묻지 않는다. "알아서 완성"처럼 전체 제작을 맡긴 경우에는 콘티를 기록하고 스스로 검토한 뒤 진행한다.

썸네일·삽화·만화는 같은 형식으로 만들지 않는다. 작품의 용도와 실제 표시 크기, 글의 요지가 장면 선택을 정한다. 썸네일에 캐릭터를 반드시 등장시키지 않는다. 사물·공간·상황만으로 요지가 더 선명하면 그 구성을 택한다. 소품은 사건뿐 아니라 취향·습관·생활감을 드러낼 수 있다. 소품을 등장시키려고 무관한 사건이나 능력을 만들지는 않는다.

만화에서는 독자가 처음 예상한 것과 다음에 발견할 것을 먼저 정하고 전환을 고른다. 중요한 전환에는 발견·연출·일반 넘기기로 바꿨을 때의 차이를 짧게 기록한다. 효과 이름부터 정하거나 모든 컷에 별도 효과를 배정하지 않는다. 구체적인 판단과 기록 형식은 `DIRECTING.md`를 따른다.

## 이미지 제작

콘티가 준비되면 [제작과 검토](references/production.md), 제작 폴더의 현재 `PROMPT.md`를 읽는다. 도구 호출은 사용 환경의 이미지 생성 도구와 관련 스킬을 따른다. Codex에서 `imagegen`을 사용할 수 있으면 해당 지침을 읽는다. 이 스킬은 특정 서비스나 모델 설치를 요구하지 않는다.

한 번에 성공한다고 보장하지 않는다. 필요한 기준 이미지와 변하지 않을 요소를 분명히 전달하고, 실패 원인에 맞는 부분 수정으로 재시도를 줄인다. 생성 수를 늘려서 좋은 그림을 고르는 방식을 기본값으로 삼지 않는다.

## 기록

결과는 정본 제작 폴더의 `scenes/YYYY-MM-DD-name/`에 저장한다. 해당 장면의 README에는 원문, 용도, 선택한 콘티, 사용한 기준 이미지, 실제 요청문과 결과 파일, 남은 문제를 적는다. 후속 회차는 관련된 이전 회차를 연결하고 재등장 인물·장소·소품의 유지 사항만 기록한다. 새 능력이나 관계를 작품 하나에서 임의로 정본에 추가하지 않는다. 연출 기록에는 채택·실험 중·제외 상태와 이유를 남기고, 제작자의 추천과 사용자의 선택을 구분한다. 한 작품의 선택을 모든 작품의 기본값으로 옮기지 않는다.

원본과 배포본은 구분한다. 사이트에 반영하는 요청이면 `AUTHORING.md`의 이미지 지침과 `DESIGN.md`의 관련 배치를 확인한다. 이미지 제작 요청 자체를 사이트 코드 수정·공개·push 승인으로 해석하지 않는다.

이 절차를 정할 때 참고한 공개 사례와 채택 범위는 [출처 기록](references/sources.md)에 있다. 평소 제작마다 다시 조사할 필요는 없다. 스킬 자체를 변경할 때의 행동 평가는 [평가 절차](evals/PROTOCOL.md)를 따른다. 일반 장면 제작에서는 평가 자료를 읽지 않는다.
